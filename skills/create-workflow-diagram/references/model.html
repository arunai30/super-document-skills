Model the explanation before the drawing.

JSON describes a small workflow. It contains no coordinates, dimensions or CSS. See the two complete models in assets/ for working examples.

Required fields

title, subtitle: concise strings
source: {title, url} — verified HTTPS reference
scope: included, omitted and proposed behavior
primaryPath: 3–7 unique node IDs in directed order
nodes: [{id, label, role, group?}]
edges: [{from, to, label, role}]
notes: [{title, body}]
designCaveat: a specific unresolved guarantee or evidence limit

Node roles: actor, service, queue, store. Edge roles: main, support, return. Every consecutive primary pair needs a real edge. Supporting nodes should relate directly to the main path or to an already placed supporting node. Their input order determines placement priority. A few feedback paths are supported; dense crossing dependencies are not.

Node labels: at most 64 characters, normally 1–3 short lines. Edge labels: at most 40 characters. Use meaningful line breaks and short words. These are practical layout limits, not writing targets. Unknown node IDs, invalid roles and per-node geometry are rejected.

Optional fields

groups: [{id, label}] — phase annotations, not containment
legend: [primaryLabel, supportLabel, feedbackLabel]
sources: [{title, url}] — additional verified HTTPS sources

Leave unused legend entries empty. Do not invent source URLs for hypothetical models; identify them as hypothetical and use a relevant, verified reference for the pattern.

Outputs and limits

share.html uses HTML/CSS for selectable nodes and computed orthogonal arrows. index.html and diagram.svg retain the vector rendering. layout.json is shared across styles. Generation uses Node standard libraries only; nothing executes inside the published page.

The accepted shape is a short main path and one supporting row. A support edge that passes through an unrelated node is rejected. Dense graphs, deployment maps and precise concurrency semantics need another view. No automatic layout can validate the architecture itself.

Keep the model and generated files together for future edits. Preserve the initial render and the code version when making repeatability claims.
